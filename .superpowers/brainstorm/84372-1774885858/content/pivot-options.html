Pivot Decision: Where's the Real Pain?

The web bidi problem is already solved by RTL Toggle. The PDF problem is unsolved.

The Landscape

Web Page Bidi Fix

Already solved by RTL Toggle and similar extensions. We'd be building a marginally better version of an existing tool.

PDF Bidi Fix

Unsolved problem. Real pain point. No good tool exists. LinkedIn, Indeed, etc. all generate broken RTL PDFs.

A

Full Pivot: PDF Fixer Only

Build a tool that takes a broken-bidi PDF (from LinkedIn, etc.) and outputs a corrected PDF with proper RTL direction.

How: User uploads PDF → we parse it with pdf-lib → detect and fix text direction → output corrected PDF

Form: Could be a web app, CLI tool, or Chrome extension that intercepts PDF downloads

Pros

  • Solves an unsolved problem
  • Clear differentiation — no competition
  • High value for Hebrew job seekers

Cons

  • PDF parsing is complex (fonts, encoding)
  • Narrower use case
  • Different tech stack needed
B

Hybrid: Smart Web Fix + PDF Export (Recommended)

Keep the smart web bidi fixer, BUT add a killer feature: "Download as fixed PDF". When user clicks download on LinkedIn etc., intercept and generate a clean RTL-correct PDF from the fixed DOM.

How: Fix DOM first (our existing plan) → when user wants PDF, use the fixed page to generate a proper PDF via html2canvas + jsPDF or browser print API

Pros

  • Best of both worlds
  • Web fixing is still useful (RTL Toggle is dumb toggle, we're smarter)
  • PDF export is the differentiator
  • Uses DOM we already fixed — less PDF parsing complexity

Cons

  • Larger scope
  • PDF from DOM won't be identical to LinkedIn's layout
C

Web Extension Only (Original Plan)

Stick with the original Bidix plan — smart per-element bidi fixing on web pages. No PDF handling.

Differentiation from RTL Toggle: Automatic (no manual toggle needed), per-element (not whole page), dynamic input handling, SPA support

Pros

  • Simplest scope
  • Well-defined architecture already designed
  • Still better than existing toggle extensions

Cons

  • Competing with existing extensions
  • Doesn't solve the PDF pain you showed
