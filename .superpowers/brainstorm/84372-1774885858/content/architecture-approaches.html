Architecture Approach

How should Bidix scan and fix elements?

A

TreeWalker Scanner (Recommended)

Use document.createTreeWalker() to efficiently walk text nodes. Group by parent element, detect direction per element, apply fixes. MutationObserver watches for new nodes and feeds them back through the same pipeline.

Pros

  • Native browser API — very fast
  • Skips non-text nodes automatically
  • Minimal memory allocation
  • Natural fit with MutationObserver

Cons

  • Slightly more complex initial setup
B

querySelectorAll Scanner

Select all text-containing elements via CSS selectors (p, span, div, h1-h6, li, td, input, textarea). Check each element's textContent, detect direction, apply fixes.

Pros

  • Simple and familiar API
  • Easy to define element scope

Cons

  • Selects elements without text too
  • Can miss dynamically added elements
  • Harder to avoid double-processing
C

Intersection Observer + Lazy Scan

Only scan elements as they enter the viewport. Combines IntersectionObserver for visibility with TreeWalker for text analysis. Fixes only visible content.

Pros

  • Best performance on large pages
  • Zero work for off-screen content

Cons

  • Visible flash when scrolling to unfixed content
  • More complex lifecycle management
  • Edge cases with fixed/sticky elements
